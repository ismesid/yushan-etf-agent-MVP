# 共用資料合約

版本：1.0｜日期：2026-10-11｜對應設計：design1001.md v0.3

資料合約是模組之間共同使用的欄位、單位與格式。第一批以 Python 標準庫的 `dataclass` 定義資料，用 `Decimal` 保存金額；HTTP、模型 SDK、檔案或資料庫操作留在各自模組。此版本供離線 demo 串接，沒有完整 D-Plan、交易驗證或正式提交功能。

## 1. 單位與格式

| 資料 | 格式 | 例子 |
|---|---|---|
| 股票代碼 | 四位字串 | `"2891"` |
| 股數 | 非負整數，單位為股 | `60000` |
| 價格、現金、NAV、成交金額 | `Decimal`；JSON 保存為十進位字串，單位為新臺幣元 | `"50.00"`、`"10000000.00"` |
| 比例、報酬、權重 | 小數；`0.04` 表示 4%；內部 PortfolioProposal 權重為 Decimal／JSON 字串 | AgentDraft 的比例與因子數值以 JSON 數字保存 |
| 資料日 | ISO 日期 | `"2026-10-14"`，demo 假設日期 |
| 時間 | 帶時區 ISO 時間；臺灣資料使用 `+08:00` | 不以本機時區推定 |
| 不知道的值 | `null`，不編造 0 或模型版本 | 未知用量、未核實時間 |

各合約載入時拒絕未定義欄位。這項限制可以攔下模型草稿夾帶的 `shares`、`orders` 或任意欄位，不能替代後續白名單、引用及全組合驗證。

載入入口為 `Contract.from_dict()`，輸出使用 `.to_dict()` 後交給 JSON。NaN／Infinity、布林值冒充整數、非整數股數、非法日期或缺時區時間會被拒絕。核心合約帶 `contract_version="1.0"`；AgentDraft 的內部 schema 版本另外保存。

## 2. 六種核心資料

| 合約 | 保存內容 | 哪個模組負責 |
|---|---|---|
| `MarketSnapshot` | 資料截止時間、價量列、來源、時間、單位與版本 | adapter／清洗 |
| `AccountSnapshot` | 現金、NAV、全部持股、結算日、帳戶來源、狀態及核對資訊 | 匯入／帳務 |
| `FeatureTable` | 股票因子、排名、計算期間、來源及缺失原因 | 因子／排名 |
| `AgentDraft` | 市場提案、選股、信心、觀察引用、全部原持股處理與簡潔理由 | Agent provider |
| `PortfolioProposal` | 完整目標權重、現金、配置方法與理由引用；退出股票仍保留零權重 | 配置／風控 |
| `ValidationReport` | 檢查結果、嚴重程度、阻擋原因與 `submission_ready` | 驗證器 |

完整原持股不能因行情或因子缺失而消失。模型只提選股與意圖，最終股數、費用及現金由程式計算。`AgentDraft` 是內部格式，不是官方 D-Plan；內部資料不能任意增添至 F04 的官方欄位。

第一批 fixture 中的草稿與因子都是人工製作的測試值。provider／模型資訊未知時保留 `null`，不得寫成實際呼叫紀錄。`AgentProvider` 只預留共同 `generate` 介面；本批沒有 Codex 或 Claude 的真實決策 adapter。

介面為 `generate(packet, draft_schema, run_dir) -> AgentResult`；結果包含草稿、provider、實際模型版本、起訖、用量與原始回應／日誌路徑。`AgentDraft.validate_context()` 檢查候選池、原持股完整覆蓋及觀察引用；`PortfolioProposal.validate_context()` 檢查完整配置，包括退出股票。這些檢查需要呼叫端傳入已核實上下文，不會自己抓資料或核對官方帳戶。

## 3. 歷史資料與可追溯時間

行情採長表，可容納同一股票的多個交易日。同一天資料被官方修正時，按資料版本保留兩份來源，不用最新值覆蓋舊證據；同一快照內日期×股票只能有一個已確認版本。需要切換歷史版本時，建立不同 `snapshot_id`／`dataset_version` 的快照，不能在單一快照混放兩份同股同日價格。

| 欄位／概念 | 用途 |
|---|---|
| `close_raw` | 未調整原始收盤價；正式股數與官方 NAV 口徑依官方規則使用 |
| `return_close`、`adjustment_status` | 因子／回測使用的價格及調整狀態；不能假裝已完成公司行動處理 |
| 資料日／內容日期 | 這筆資料描述哪個交易日或期間 |
| `known_at` | 有證據顯示何時已公開可知；無法確認時保留空值 |
| `fetched_at` | 本程式實際取得時刻，不能改成歷史時刻 |
| `raw_sha256` | 原始內容的雜湊，用來識別相同或被改過的資料 |
| `data_version` | 用了哪一份資料版本；和清洗／因子版本一起保存 |

某月營收的資料期是 9 月，不表示 9 月底已知。歷史回測只能讀取當時已知且未超過截止時間的版本；今天補抓的修正版不能默默回填成當時可知版本。只有歷史價格也不代表已驗證時間防洩漏。

存儲方向是 SQLite 保存帳務及必要索引，原始回應、清洗行情及執行產物保存 JSON／CSV。第一批尚未建 SQLite 或正式行情存檔；具體表格、快取鍵與取資料方式留到對應批次討論。

## 4. 預留訓練、驗證與測試期間

新增 `DatasetSplitPlan`，為日後回測／訓練保存按時間切分的計畫。`train` 是用來學習參數的資料；`validation` 用於比較方法或調參；`test` 是預先保留、最後才評估的較新資料。較新的期間不能都被用作訓練或反覆調參後仍當獨立測試。

本批檢查日期合法、起訖順序與三個期間不重疊，保留 `label_horizon_trading_days` 與 `gap_trading_days`。例如預測未來 5 個交易日報酬，訓練期間末端的標籤會用到未來價格，需依真實交易日曆隔離跨界樣本。這兩個欄位只是計畫：真正交易日 gap、標籤終點、purge（排除跨界標籤）、資料覆蓋率及滾動回測仍需後續實作驗證。

切分欄位為 `dataset_version`、`train_start/end`、`validation_start/end`、`test_start/end`、`label_horizon_trading_days`、`gap_trading_days`、`final_test_locked`。目前要求標籤期間為正整數、gap 設定至少等於標籤期間、`final_test_locked=true`。這只表示有鎖定計畫，沒有實作禁止讀取測試資料的訓練流程。任何具體欄位值仍可在後續討論改版。

fixture 的說明計畫如下：

| 期間 | 起訖日期 |
|---|---|
| 訓練 | 2020-01-01～2023-12-29 |
| 驗證 | 2024-01-15～2024-12-31 |
| 保留測試 | 2025-01-15～2026-09-30 |

示例的標籤／gap 都設為 5 個交易日；這是解釋合約用假設，不是已決定年限或策略設定，也不表示已取得這些歷史資料或已核對端點是交易日。實際期間須依來源可取得範圍、預測標籤及至少可供獨立評估的測試長度共同決定。初版因子所需 21 筆價格／約 90 天補抓，是盤前因子需求，不能當成足夠訓練與回測的歷史長度。

後續原則：不隨機打散股票日資料切分；同一天所有股票依同一時間邊界分組。擬合標準化或缺值處理參數只使用訓練資料。預先鎖定測試期與資料版本；每次滾動測試保留各折的訓練截止時間。現在的 F05 名單不保證適合無偏差的長期歷史回測，還須評估存續偏差與當時可投資股票範圍。

## 5. 既有持股 demo 帳

本批建立的是人工測試帳：25 檔持股、現金 1,000 萬元、NAV 1 億元。2891 為 60,000 股×假價格 50 元＝300 萬元；其餘 24 檔每檔 58,000 股×假價格 62.50 元＝362.5 萬元，合計 8,700 萬元。總股票價值 9,000 萬元加現金，等於 1 億元。

fixture 假設決策日為 2026-10-15、前一交易日為 2026-10-14；只有測試日曆，未取得真實官方日曆。行情共有 26 列：25 檔前收，加上 2891 的 2026-10-13 一列，以展示同一股票可有多個日期。因子是人工假值，沒有 21 日實際序列或因子計算完成證據。O1–O25 為 fixture 內部引用，不是官方完整 source→observation 證據鏈。

`status=demo`、來源為人工 fixture、`reconciled=false`。完整持股可用於之後驗證續抱、加碼、減碼與賣出，不是主辦方正式帳。當 `PortfolioProposal` 的測試值寫 2891 權重 4% 時，單股手算目標為 80,000 股；第一批不執行股數推導、費用、成交或庫存更新。

## 6. 官方、自訂與未確認事項

官方內容保留 F01–F09 原檔。本批的六種內部合約、資料切分方法、demo 數值及存儲方式是實作決定，不是競賽規定。設計中的因子權重、內部單股上限、產業上限、換手限制等尚待逐批確認，第一批不把它們定為已同意策略參數。

正式期初帳戶、截止時刻、資訊區間、費用取整、公司行動及無成交口徑仍未確認。缺這些規則或正式核對證據時，不能宣稱正式可提交。第一批離線示例固定為 `submission_ready=false`。

## 7. 重跑本批示例

從專案根目錄開 PowerShell，使用現有 Python 即可，不需安裝第三方套件：

```powershell
$env:PYTHONPATH = (Resolve-Path 'src').Path
python -B -m etf_agent.cli --help
python -B -m etf_agent.cli contracts-demo --fixture tests/fixtures/contracts_demo.json
python -B -m unittest discover -s tests -p test_contracts.py -v
```

本批實測：help 與 demo 回傳 exit code 0；demo 顯示六種核心合約、DatasetSplitPlan 及 AgentResult 共八種 JSON 往返 PASS，25 檔帳的股票價值 9,000 萬元加現金 1,000 萬元，核對 NAV 1 億元 PASS。30 項單元測試通過，缺檔輸入回傳 exit code 2 與可讀錯誤。

內部 schema 已檢查 JSON 可讀及結構內容；未安裝或執行 `jsonschema` 驗證。官方 F04 的結構／語意驗證、21 日因子、股數、費用及帳務更新留在後續批次。
